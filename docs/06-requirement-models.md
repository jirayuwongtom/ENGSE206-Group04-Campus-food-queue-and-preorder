## 2. Acceptance Criteria

### AC-01 —  การแจ้งเตือนเมื่ออาหารพร้อมรับโดยไม่ต้องฟังเสียงเรียก (FR-01)

- Given : ออเดอร์หมายเลข #105 ของลูกค้า A มีสถานะเปลี่ยนเป็น "พร้อมรับ"
- When : พนักงานร้านค้าทำการกดเปลี่ยนสถานะออเดอร์บนหน้าจอควบคุม
- Then : ระบบส่งสัญญาณสั่นเตือนและแสดงข้อความแจ้งเตือนบนโทรศัพท์มือถือของลูกค้า A ทันที

### AC-02 —  การเรียงลำดับออเดอร์ตามเวลาที่ได้รับจริง (FR-04)

- Given : ในระบบมีออเดอร์ที่สั่งและชำระจำลองเสร็จสิ้นค้างอยู่ 2 รายการ ได้แก่ ออเดอร์หมายเลข #101 (ข้าวมันไก่ต้ม สั่งเวลา 12:00 น.) และออเดอร์หมายเลข #102 (ข้าวขาหมู สั่งเวลา 12:02 น.)
- When : พนักงานร้านค้าทำการเรียกดูรายการคิวบนหน้าจอระบบควบคุมหลักของร้านค้า
- Then : ระบบต้องจัดแสดงรายการออเดอร์ #101 ไว้ที่ส่วนบนสุดของตารางในสถานะ "ออเดอร์ใหม่" และแสดงรายการออเดอร์ #102 อยู่ในลำดับถัดลงมาอย่างถูกต้องตามกฎการเรียงลำดับก่อน-หลัง โดยไม่มีความผิดเพี้ยน

### AC-03 —   การเข้าถึงรายงานสถิติความหนาแน่นคิว (FR-06 , FR-04)
- Given : ระบบได้บันทึกข้อมูลและจำนวนคิวที่เกิดขึ้นในช่วงพักเที่ยงของแต่ละร้านค้าสะสมเป็นเวลา 1 สัปดาห์
- When : ผู้ดูแลพื้นที่อาหารทำการเข้าสู่ระบบฝั่งแอดมินและกดเลือกเรียกดูรายงาน "สถิติความหนาแน่นคิวตามช่วงเวลา" ของเดือนปัจจุบัน
- Then : ระบบต้องแสดงผลกราฟหรือตารางแจกแจงปริมาณคิวและเวลารอเฉลี่ยรายชั่วโมงได้อย่างถูกต้อง โดยชี้ชัดว่าช่วงเวลาใดมีความหนาแน่นสูงสุด เพื่อให้ผู้ดูแลสามารถนำข้อมูลนี้ไปพิมพ์หรือส่งออกสำหรับบริหารจัดการพื้นที่ล่วงหน้าได้

### AC-04 —   การประหยัดขั้นตอนในการเปลี่ยนสถานะของพนักงาน (NFR-03)
- Given : พนักงานร้านกำลังเปิดหน้าตารางคิวสั่งอาหารบนอุปกรณ์ฝั่งร้านค้า
- When : พนักงานต้องการเปลี่ยนสถานะออเดอร์รายการที่เลือกจาก "ออเดอร์ใหม่" ไปเป็น "กำลังทำ"
- Then : ระบบต้องอนุญาตให้พนักงานดำเนินการเสร็จสิ้นได้ด้วยการสัมผัส/คลิกหน้าจอไม่เกิน 2 ครั้ง โดยไม่ต้องผ่านขั้นตอนการเปิดป๊อปอัปยืนยันหลายชั้น

## 4. Use Case Specification

### UC-01 — ตรวจสอบสถานะอาหารและคิว (Monitor Order & Queue Status)

| Field | Detail |
|---|---|
| Primary Actor | นักศึกษา / ลูกค้า |
| Goal | รับทราบหมายเลขคิวปัจจุบัน และสถานะการปรุงอาหารผ่านระบบ |
| Trigger | ลูกค้าเปิดหน้าติดตามสถานะคิวบนแอปพลิเคชัน |
| Preconditions | 1. ลูกค้าทำรายการสั่งซื้อสำเร็จในระบบ<br>2. อุปกรณ์ของลูกค้าเชื่อมต่ออินเทอร์เน็ต |
| Main Success Scenario | 1. Actor: ลูกค้าเปิดดูหน้าติดตามคิวออเดอร์ของตนเอง<br/>2. System: ระบบดึงข้อมูลหมายเลขคิว และสถานะการปรุงอาหารล่าสุด<br>3. System: ระบบแสดงผลหมายเลขคิว และสถานะออเดอร์ให้ลูกค้าเห็นชัดเจน<br>4. Actor: ลูกค้ารอรับอาหารโดยไม่ต้องยืนเฝ้าหน้าเคาน์เตอร์<br>5. System: เมื่อพนักงานอัปเดตสถานะเป็นพร้อมรับ ระบบส่งสัญญาณแจ้งเตือนไปยังมือถือของลูกค้า<br>6. Actor: ลูกค้าแสดงหมายเลขคิวบนแอปพลิเคชันเพื่อรับอาหารหน้าร้าน |
| Alternate / Exception Flows | At step 2 (Exception) : หากระบบไม่พบข้อมูลออเดอร์ของลูกค้า<br>- Condition: ไม่พบรายการออเดอร์ที่รอดำเนินการ<br>- System Response: ระบบแสดงข้อความไม่พบออเดอร์และแนะนำให้ตรวจสอบประวัติการสั่งซื้อ |
| Postconditions | ลูกค้ารับทราบสถานะคิวถูกต้องและรับอาหารสำเร็จ |
| Related Requirements | FR-01 |

### UC-02 — จัดลำดับคิวและปรุงอาหาร (Manage & Cook by Queue FIFO)

| Field | Detail |
|---|---|
| Primary Actor | พนักงานร้าน |
| Goal | ดำเนินการปรุงอาหารตามลำดับคิว FIFO และเปลี่ยนสถานะออเดอร์ในระบบ |
| Trigger | มีรายการออเดอร์ใหม่เข้ามาในระบบ |
| Preconditions | พนักงานร้านเข้าสู่ระบบฝั่งร้านค้าและเปิดหน้าจอควบคุมคิว |
| Main Success Scenario | 1. System: ระบบจัดแสดงรายการออเดอร์ใหม่เรียงตามลำดับเวลารับออเดอร์ (FIFO)<br>2. Actor: พนักงานตรวจสอบรายการอาหารและกดเปลี่ยนสถานะเป็นกำลังทำ<br>3. System: ระบบอัปเดตสถานะเป็นกำลังทำ และแสดงผลไปยังฝั่งลูกค้า<br>4. Actor: พนักงานปรุงอาหารตามลำดับจนเสร็จสิ้น<br>5. Actor: พนักงานวางอาหารที่จุดส่งมอบและกดเปลี่ยนสถานะเป็นพร้อมรับ<br>6. System: ระบบส่งสัญญาณแจ้งเตือนไปยังโทรศัพท์ของลูกค้า<br>7. Actor: พนักงานตรวจสอบหมายเลขคิว ยื่นอาหารให้ลูกค้า และกดเปลี่ยนสถานะเป็นส่งมอบสำเร็จ |
| Alternate / Exception Flows | At step 2 (Quality Constraint - NFR-03):<br>- Condition: พนักงานกดเปลี่ยนสถานะออเดอร์บนหน้าจอ<br>- System Response: ระบบต้องบันทึกการเปลี่ยนสถานะโดยใช้การสัมผัสไม่เกิน 2 คลิก โดยไม่มีป๊อปอัปยืนยันหลายขั้นตอน |
| Postconditions | ออเดอร์ได้รับการปรุงและส่งมอบตามลำดับ FIFO สำเร็จ |
| Related Requirements | FR-04, NFR-03 |

### UC-03 — ตรวจสอบสถิติความหนาแน่นคิว (Monitor Queue Density Statistics)

| Field | Detail |
|---|---|
| Primary Actor | ผู้ดูแลพื้นที่อาหาร |
| Goal | เรียกดูรายงานสถิติปริมาณคิวและความหนาแน่นตามช่วงเวลา |
| Trigger | ผู้ดูแลพื้นที่ต้องการข้อมูลสถิติเพื่อวางแผนบริหารจัดการพื้นที่โรงอาหาร |
| Preconditions | ผู้ดูแลพื้นที่อาหารเข้าสู่ระบบในสิทธิ์แอดมิน |
| Main Success Scenario | 1. Actor: ผู้ดูแลพื้นที่เข้าสู่หน้ารายงานสถิติบนระบบแอดมิน<br>2. Actor: เลือกช่วงเวลาหรือช่วงเดือนที่ต้องการเรียกดูข้อมูล<br>3. System: ระบบรวบรวมประวัติคิวและเวลารอเฉลี่ยของแต่ละร้านค้า<br>4. System: ระบบแสดงผลรายงานสถิติความหนาแน่นคิวและเวลารอเฉลี่ยรายชั่วโมง<br>5. Actor: ผู้ดูแลพื้นที่นำข้อมูลไปใช้วางแผนจัดระเบียบพื้นที่ส่วนกลาง |
| Alternate / Exception Flows | At step 3 (Exception): หากยังไม่มีข้อมูลสถิติสะสมในระบบ<br>- Condition: ระบบเปิดใช้งานใหม่ยังไม่มีประวัติบันทึก<br>- System Response: ระบบแสดงข้อความยังไม่มีข้อมูลสะสมเพียงพอสำหรับการสร้างรายงาน |
| Postconditions | ผู้ดูแลพื้นที่อาหารได้รับข้อมูลสถิติสำหรับบริหารจัดการพื้นที่ส่วนกลาง |
| Related Requirements | FR-06 |
