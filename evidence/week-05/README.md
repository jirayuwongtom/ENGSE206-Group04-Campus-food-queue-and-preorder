# Evidence — Week 05: วิเคราะห์และจัดลำดับความสำคัญ

## ข้อมูลกิจกรรม

- วันที่ส่ง Backlog: 11/08/2569 ตามใบส่งงาน Week 05
- วันที่ทำ Artefact Health Check: 18/08/2569 ตาม worklog ของทีม
- กิจกรรม: จัดหมวด requirement, จัดลำดับด้วย MoSCoW และตรวจความพร้อมของเอกสารก่อนทำ baseline
- ผู้ร่วมงานที่ระบุใน worklog วันที่ 18/08/2569: ศักดิ์ณรงค์และจิรายุ
- ขอบเขตหลักฐาน: ใช้เอกสารใน repository และบันทึกที่กลุ่มทำไว้ ไม่มีข้อมูลสัมภาษณ์ใหม่ในชุดนี้

## สิ่งที่ทำและพบ

ทีมจัด requirement เป็น Functional, Business Rule, Non-functional และ Issue พร้อมกำหนดความสำคัญและเหตุผลไว้ใน Backlog กับ Prioritization Rationale ส่วนคำถามที่ยังไม่มีคำตอบแยกไว้ใน Open Questions and Issues

Artefact Health Check ระบุว่าเอกสาร Backlog ยังขาดเกณฑ์ตรวจรับที่ชัดเจน และมีถ้อยคำบางข้อที่วัดผลได้ยาก จึงมีการบันทึกการแก้ไขต่อใน worklog และ decision log วันที่ 18/08/2569

อย่างไรก็ตาม ไฟล์ docs/05-requirement-backlog.md ที่อยู่ใน repository ปัจจุบันยังไม่มีคอลัมน์ Acceptance Measure แม้ decision log และ traceability log จะระบุว่าเพิ่มแล้ว ดังนั้นควรตรวจไฟล์ Backlog ให้ตรงกับบันทึกการแก้ไขก่อนอ้างว่าประเด็นนี้ปิดแล้ว

## ผลต่อเอกสาร

- Requirement ถูกจัดลำดับและเชื่อมโยงกับ RC/Evidence ใน docs/05-requirement-backlog.md
- เหตุผลการจัดลำดับอยู่ใน docs/05-prioritization-rationale.md
- ประเด็นที่ต้องถามต่อและรายการที่พักไว้ อยู่ใน docs/05-open-questions-and-issues.md
- ผลตรวจเอกสารเบื้องต้นอยู่ใน artefact-health-check.md
- บันทึกกิจกรรมและการตัดสินใจเพิ่มเติมอยู่ใน project-management/team-worklog.md และ project-management/decision-log.md
